## 7. Source-of-truth / manifest review

Code inspection and the adversarial results confirm:

1. `finalize_result.py` requires actual primary raw responses and actual primary run manifest.
2. It calls `verify_supplied_scored()`, which reruns the real scorer and requires both exact JSON equality and exact byte equality with the supplied scored artifact.
3. Run provenance includes the SHA-256 calculated from the **actual supplied manifest bytes**.
4. Scorer manifest validation checks format/version, run kind, run/series/repetition IDs, execution nonce, exact case scope and expected response count, graph/runtime/case-index fingerprints, both arm prompt fingerprints, prepared prompt-set fingerprint, and configuration fingerprint.
5. Blind provenance is recomputed against the same source responses.
6. Semantic merge is recomputed and the supplied semantic artifact must equal the recomputed artifact.
7. Stability receives triples `raw responses + actual run manifest + scored artifact`, reruns scorer independently for every triple, and requires distinct raw SHA and distinct canonical response-set fingerprint in addition to manifest/run/repetition/nonce/scored uniqueness.
8. Finalization recomputes stability and requires the supplied stability artifact to match the recomputed output.
9. Primary/stability model, provider, generation parameters, graph fingerprint, runtime fingerprint, case-index fingerprint and arm prompt fingerprints are cross-checked.
10. Final verdict uses recomputed gates; downstream JSON cannot repair a broken source chain.

No downstream-only JSON edit path to a false formal PASS was found.

## 9. Artifact-level provenance limitation

The local static harness does **not** cryptographically prove that three response files came from three physically independent external model/API executions, nor can local hashes prove reviewer independence without a trusted external signer. A submitter who edits the authoritative raw response artifacts can create distinct file/canonical fingerprints.

This is **not** a release-blocking defect under the audit boundary: the requirement is to prevent one source run or a deterministic FAIL from being converted to formal PASS merely by editing downstream release JSON. Independence of the later real executions and evaluator separation remains a procedural control.
