# Contributing / Участие в разработке

## RU

HBBA — исследовательский проект с **замороженным Scientific Core v0.7.0.28**. Contributions приветствуются, но важно различать изменения продукта/UI, новые исследовательские ветки и изменения frozen core.

### Подходящие contributions

- воспроизводимые bug reports;
- исправления доступности и локализации;
- улучшение документации;
- независимые репликации benchmark-результатов;
- новые preregistered empirical studies как отдельные ветки/пакеты;
- исправления evidence mapping с прослеживаемыми источниками и явным review.

### Правило frozen core

Не изменяйте молча canonical node/edge/behavior topology, evidence grades, provenance, Scenario/Actor schemas, runtime contracts или исторические benchmark conclusions и не представляйте изменённую систему как тот же frozen core.

Научные изменения требуют новой research version с собственным provenance и validation.

### Научные утверждения

Всегда разделяйте:

1. software correctness;
2. formal graph capability;
3. benchmark performance;
4. real-world behavioral validity.

Evidence одного уровня не должно выдаваться за доказательство другого.

## EN

HBBA is a research-oriented project with a **frozen Scientific Core v0.7.0.28**. Contributions are welcome, but product/UI work, new research branches, and frozen-core changes must be treated as different classes of change.

### Good contribution types

- reproducible bug reports;
- accessibility and localization fixes;
- documentation improvements;
- independently reproduced benchmark results;
- new preregistered empirical studies built as separate branches/packages;
- evidence corrections supported by traceable sources and explicit review.

### Frozen-core rule

Do not silently alter canonical node/edge/behavior topology, evidence grades, provenance, Scenario/Actor schemas, runtime contracts, or historical benchmark conclusions and present the result as the same frozen core.

Scientific changes require a new research version with its own provenance and validation.

### Scientific claims

Always distinguish:

1. software correctness;
2. formal graph capability;
3. benchmark performance;
4. real-world behavioral validity.

Evidence at one level must not be presented as proof at another.
